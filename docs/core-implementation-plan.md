# Moke core implementation plan

Build one complete drawing review with a supported issue, an engineer-corrected false alarm, a targeted second look, and a revision recheck. Bun and Effect provide the application infrastructure. Pi Durable supplies agent execution behind a narrow application service. Start locally; add the selected Modal handoff after the local workflow passes its recovery checks.

This is an implementation plan, not a claim that the review engine exists. The working baseline is the Electron shell, compiled Bun backend, Effect RPC, SQLite recovery, and a separate UI study. Bun is pinned to 1.4.4 and Effect to 4.0.4. Source evidence and unresolved compatibility questions are recorded in [Core implementation research](research/core-implementation-sources.md).

## Decisions and scope

The current repository and [runtime decision](review-runtime.md) supersede the older planning packet's pnpm/Vite+ toolchain, main-process application services, and deferred Bun engine. The approved chat and findings study supersedes that packet's drawing-first window layout. Preserve project/conversation navigation, the findings popover, and the source pane. A review conversation is a view of real application work, rather than an unrestricted assistant.

The initial case contains one engineering rule, multiple instances, one floor, about two related sheets, and one revised PDF. Select the rule and object class using actual drawing evidence. Panel clearance remains a candidate. Record applicability and a verified source before encoding a code threshold. If those cannot be established, choose a supported coordination check and label it accordingly.

Required local outcomes:

- Import permissioned PDFs and retain immutable originals, sheet coverage, and source hashes.
- Render an overview and a legible detail region directly from the original PDF.
- Let Muse request a specific missing observation; use SAM where the development experiment establishes a useful contribution.
- Present evidence, accepted inputs, rule applicability, and repeatable arithmetic for each result.
- Correct an accepted input, withdraw a false alarm when warranted, and leave unrelated check runs unchanged.
- Apply Rev B with confirmed sheet correspondence, mark affected results stale, and recheck them without losing history.
- Pause, cancel, reopen, and recover without duplicate domain mutations or automatic reissue of an uncertain paid call.

Accounts, sync, arbitrary drawing registration, autonomous redesign, a general rule library, a second agent framework, and automatic updates are outside this core. Maintain existing platform CI; choose one primary demo platform before investing in PDF packaging. Windows x64 is the packet's proposed target, not a newly confirmed requirement.

## Application contracts and data

Keep shared contracts under `src/lib/review/` using `#lib` imports. Put implementation under `backend/review/`, `backend/documents/` and `backend/inference/` as behavior warrants. These are cohesive modules, not a mandatory hierarchy. Extend `backend/application.ts`, the shared backend RPC group, and Electron's authorized proxy. The renderer sees only user operations; import/export paths and credential operations remain shell capabilities.

In unit 1, port the approved project/conversation navigation, findings popover and source pane into `src/routes/+page.svelte` and reusable renderer components. Unit 2 connects the evidence/calculation inspector. The minimal production workbench replaces the running notes screen; rebuilding the study alone does not satisfy either gate. Persist user/reviewer messages and references to Pi transcript entries; derive progress rows from application events rather than storing a second copy of every agent message.

### Persistent records

| Record family                               | Required information and invariants                                                                                                                                                                                       |

| Finding and dependency edges                | Stable issue identity, historical check runs, evidence references and explicit edges from facts/calibrations to derived measurements/checks. Finding closure and user task completion remain separate.                    |
| Review run, work item and operation receipt | Engine/schema/prompt versions, input snapshot, durable request ID, stable tool operation ID, owner generation, state, committed result and event sequence. A unique operation ID returns its stored result on redelivery. |

Use new numbered migrations after `0001_notes.sql`; applied migrations remain immutable. Add constraints for operation IDs, fact version uniqueness and project-qualified references. Initialize and verify `PRAGMA foreign_keys=ON` before transactions on every newly opened domain or journal connection that relies on those constraints. Apply and read back connection-local durability settings too; the migration connection's configuration does not configure later connections. Do not use a transcript as the canonical finding database or introduce an event-sourcing framework. Append-only facts and receipts plus current-result pointers and an event table are sufficient.

### State and concurrency rules

Keep separate state axes for evidence acceptance, check outcome, citation verification, reviewer closure and user completion. Check outcomes include `pending`, `running`, `needs_evidence`, `supported_issue`, `checked_no_issue`, `stale`, and `outside_scope`. Execution distinguishes queued/running, pausing/paused, waiting for reviewer, uncertain attempt, cancelling/cancelled, completed and failed. Define legal transitions and resume conditions explicitly in schemas and pure domain functions.

Each mutation supplies a command ID, input fingerprint and expected fact/scope version. A transaction first looks up an existing command receipt: matching input returns the stored result even if the expected version is now old; reuse with different input is rejected. For a new command, verify the expected version, write new facts and dependency invalidations, store the command result, and append its durable event together. A late model result may be stored historically, but cannot replace a current result when its source revision, accepted-fact versions, rule version or owner generation has changed.

Corrections can arrive while inference is in flight: commit the correction first, mark affected results stale, and reject stale promotion on completion. On a global source revision change, stale every result that depends on a changed or unconfirmed sheet. Preserve unchanged results only after correspondence and unchanged dependencies are established. An old PDF hash alone cannot stand in for Rev B evidence.

## PDF and evidence pipeline

Start with `pdfjs-dist` and its first-party Node rendering approach using `@napi-rs/canvas`. This is a candidate pending Bun and compiled packaging tests, not an established compatibility claim. Evaluate the actual native addon, PDF worker asset, CMaps, standard fonts and any WASM assets in the installed package. Pin exact versions and record licenses. Do not add Sharp or a second image library when Bun's image pipeline covers the operation.

The unit 0 packaging probe inspects the selected published package's canvas dependency, optional platform binary and bundler resolution. Current PDF.js source already uses `@napi-rs/canvas`; test an override only if that exact package demonstrates a resolution failure. The compiled probe must locate the addon and all render assets without a developer `node_modules` directory.

Import is a shell-selected capability: Electron chooses a file, Bun validates and stages it, hashes its bytes, copies the immutable original, inventories the pages and commits the manifest. Renderer and model arguments use project-qualified artifact IDs and bounded regions, never arbitrary filesystem paths or URLs. Reject inaccessible/encrypted/malformed/oversized PDFs as explicit states. Bound source bytes, page count, decoded pixels, crop area, render time and concurrent jobs in parsed configuration.

Store canonical geometry in PDF page coordinates together with the page box, rotation and user unit. Record affine forward/inverse transforms through the PDF viewport, region origin, output pixels, provider resize and padding. Store actual submitted dimensions and the provider's grounding/mask coordinate convention. Do not assume all returned coordinates are normalized alike or normalize away rotation. Round only for display.

For the current SAM protocol, preserve source-pixel boxes with inclusive `x2`/`y2`, the submitted image's displayed `w`/`h` after orientation, and the mask's own raster dimensions. Convert inclusive box edges deliberately when a renderer uses half-open rectangles. Pin the official `@meta-sam/parser` and supported mask encoding; use its parser/decoder rather than hand-written token parsing. Validate confidence-bearing output support for the selected parser version. Geometry tests include single-pixel boxes, edge pixels, orientation and the crop-to-PDF inverse transform.

Render small overview images for navigation. Render detail directly from the original selected region, initially testing 300 DPI. Clip the render viewport to the requested region rather than allocating a full 24-by-36-inch page at that DPI. Use `Bun.Image` for deliberate final encoding/resizing with dimensions recorded. Avoid hidden Pi image-tool resizing: Moke supplies image blocks and owns their provenance.

Publish artifacts to a temporary file on the destination filesystem, close/flush and sync as required, verify hash/dimensions, then rename into a content-addressed location before committing its database reference. Distinguish process-crash recovery from stronger power-loss claims. On startup, reconcile temporary files and committed manifests; keep unreferenced completed artifacts until safe collection. A missing artifact produces a recoverable error, not a check with empty evidence.

The UI reads bounded artifact chunks or previews through an authorized application capability and creates renderer-local Blob URLs. Add a renderer-only PDF.js build for interactive page viewing if needed; keep canvas/native modules in Bun. The backend's current 64 KiB setting limits incoming HTTP request bodies, not responses. Keep import commands small and shell-mediated. Bound artifact response chunks separately for memory and cancellation, and test serialization on both RPC hops. Preserve loopback origin rejection and top-frame authorization.

## Review loop and deterministic checks

The agent receives selected scope, rule requirements, current proposed/accepted evidence and remaining budget. Register only these capabilities, with application-owned schemas:

| Tool capability                | Policy                                                                                                                                                            |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inspect selected sheet/context | Returns bounded text, overview and coverage from the allowed project and revision.                                                                                |
| Render source region           | Requires an allowed sheet, valid coordinates and a reason tied to a missing fact. Uses a content-addressed cache and stable operation receipt.                    |
| Segment source region          | Sends the exact image to SAM; decodes bounded masks/boxes into proposals with their transform and receipt. A recovered paid SAM attempt uses the provider ledger. |
| Propose observations           | Stores typed candidates and evidence references. Cannot accept a fact or overwrite a reviewer correction.                                                         |
| Evaluate selected check        | Runs deterministic code against current accepted input versions and applicability. Returns exact arithmetic or the missing prerequisites.                         |
| Ask reviewer / finish review   | Persists a question or terminal summary and yields execution. Neither completes engineering evidence by itself.                                                   |

Effect Schema is authoritative. Start descriptor generation with Effect 4's `Schema.toJsonSchemaDocument`, which emits draft 2020-12 for the schema's JSON codec, then adapt only the subset the pinned Pi/TypeBox validator supports. Align excess-property rejection on both sides. Probe branded IDs, tagged unions, bounds, `$ref`, `additionalProperties` and the JSON codec's encoded/decoded differences, including examples rejected on either side. Simplify tool payloads when equivalent conversion is unavailable; do not maintain two independent hand-written validation systems. Decode arguments again into domain types and validate project membership, source versions, region bounds and allowed operations before execution. Drawings and model text are untrusted data, not tool authority. Do not install Pi `CodingTools`, arbitrary shell, filesystem reader or unrestricted URL fetch capabilities.

Declare `replay: "safe"` explicitly for render, segment, propose, evaluate and every other tool expected to recover by redelivery. That declaration is justified only by stable operation IDs and stored results. A replay before the domain write can perform the operation once; after the domain commit it returns the receipt. A segment replay with an uncertain paid attempt blocks for reconciliation instead of resending. Tools without a proven safe replay strategy remain explicitly unsafe and surface interruption.

Proposed starting limits are two additional acquisition rounds per check, twelve total tool calls per run, one model request at a time and one PDF job at a time. Set `toolExecution: "sequential"` explicitly, matching the current Pi source, and verify the pinned package accepts it. Parse a mandatory elapsed-time ceiling, output-token ceiling and cost budget before admitting a run. Calibrate actual numeric time/token/cost defaults in the first real provider experiment. Repeated identical unproductive requests terminate with `needs_evidence`. All repair requests and SAM calls count toward the same ledger; compaction remains disabled initially.

A model never supplies the final engineering arithmetic or acceptance decision. Missing calibration, conflicting dimensions, unverified applicability, unreadable evidence or unsupported geometry produces `needs_evidence` or `outside_scope`. A model-only observation remains proposed. The engineer explicitly accepts the operands used by the first demonstration's check. SAM masks help locate boundaries; they do not establish a physical dimension.

## Pi adapter, recovery and paid-call policy

### One execution owner

Expose `ReviewExecution` operations to submit, pause, resume, cancel, inspect and observe a run. Its Layer acquires the Chord/Pi lifecycle, registers tools/models and disposes them under the application scope. The current backend uses a top-level `Effect.runPromise`; unit 4 introduces one `ManagedRuntime` for application services and callback entry, preserving stdin ownership, readiness and the bounded shutdown behavior. Imperative Pi callbacks enter that runtime. Propagate cancellation both ways and finish cleanup before closing storage. Do not create an unmanaged runtime for every tool call.

Use a dedicated Pi journal per review session under the application data directory. Keep domain SQLite and Pi storage ownership separate. Before opening application databases or journals, the backend must acquire an exclusive process ownership resource for the canonical local data directory. Use a dedicated SQLite lock file outside exported/restored project state, with zero busy wait and a held `BEGIN IMMEDIATE` write transaction; a second process fails before execution, and process death releases its OS-managed lock. The lock connection is scoped to backend ownership and performs no application queries. Record this deliberate lifetime scope in `docs/data.md`; domain queries remain scoped per operation. Never unlink/restore the live lock file, and limit this mechanism to supported local filesystems. Test two independent compiled backends and crash/reacquire. Electron's single-instance lock and a process-local session registry are additional guards, not the enforcement mechanism. Cloud ownership is a separate protocol below.

The first storage candidate is Pi's existing `openNodeSqliteStorage` adapter under Bun's `node:sqlite` compatibility API. Moke already uses that compatibility API for migration and backup. Test the existing adapter on compiled Bun before writing a new one. Its async transaction executor explicitly serializes operations and issues `BEGIN IMMEDIATE`/`COMMIT`/`ROLLBACK`; it does not pass an async callback to Bun's synchronous transaction helper. Pin exact Pi Durable, Pi AI and Chord versions and record their published exports. The journal connection is scoped to the active `ReviewExecution` session and closes before maintenance. Document this distinct harness resource lifetime in `docs/data.md`; Moke's domain data continues through scoped Effect SQL operations.

Only if the existing adapter fails a recorded Bun conformance or packaging case should a custom facade be considered. Prefer Effect SQL when it can preserve transaction-bound context across the Promise bridge: scope standalone operations, route every callback query through its transaction executor, queue unrelated work, and reject expired handles. Never re-enter an unscoped client that waits on the transaction's own lease. Verify multi-statement `exec`, positional bindings, row/null conversion, rollback failures and close/drain behavior. Never pass an async callback to Bun's synchronous `Database.transaction`. Do not implement a second harness to evade a failed gate.

Start from the existing adapter's documented WAL and `synchronous=NORMAL` guarantee and verify process-crash behavior. Do not claim power-loss preservation of its newest commits. `synchronous=FULL` is a separate configuration/custom-adapter experiment when needed, not a reason to replace the adapter first. Domain mutations and Pi receipts still span two stores: commit the domain result and operation receipt atomically first; a replay returns that receipt rather than repeating the mutation. A process crash after the domain commit and before Pi's receipt must be a dedicated test.

### Attempt ledger

Before every paid dispatch, reserve budget and commit an intent with a stable logical key derived from the run and durable generation/tool identity, including compaction purpose. Hash inputs for diagnostics; identical prompts in distinct legitimate turns are not the same operation. Persist a returned response ID and completed response receipt as soon as available. Promote output only after schema/source/version validation.

Persisted intent with no final receipt becomes uncertain after an interrupted dispatch. A known retrievable response ID can be reconciled through a verified route. If the provider cannot retrieve it, present the uncertainty and permit an explicit recorded new attempt; do not promise exactly-once billing or treat abort as a refund. An HTTP timeout or local cancellation after submission is not proof that no billable work occurred.

Pi can resume unfinished generation. Enforce admission in the registered model-provider dispatch seam and count sends at the underlying HTTP transport. Set Pi provider-internal retry counts explicitly to zero initially, including the Responses adapter's `retryProviderRequest` path, and disable harness-level automatic retries until an application decision has reconciled the attempt. A wrapper around a logical model call is insufficient if a lower layer can issue another HTTP request.

Unit 0 must demonstrate a supported way to carry durable generation task identity and attempt purpose from the Pi task boundary to that seam. Pi's provider `sessionId` is conversation affinity, not a request ID. Do not substitute process-local counters or prompt hashes for durable identity. If the published API cannot supply this correlation, the Pi gate fails pending a concrete adapter change. Disable automatic compaction in the initial short-context core; reaching the context ceiling yields an explicit limit. Enabling compaction later requires the same durable identity and send-count tests for compaction requests. SAM calls use their stable tool operation IDs. Unresolved attempts must produce zero additional HTTP sends after timeout, close, crash and reopen. Hook failures may be skipped by Pi, so hooks alone cannot enforce authorization, budgets or the uncertain-call rule.

RPC disconnect only detaches observation; cancelling a Pi wait is not a job cancellation. Pause durably closes an application admission gate, serialized with the start of every model/tool operation, then drains the operation already admitted to a committed boundary. Prove that no next operation crosses the gate. Reopen reads the paused state before starting Pi's scheduler. Cancel persists intent first, invokes explicit Pi conversation/task abort, aborts processing, and attempts provider cancellation where supported. A late receipt may update history and cost without making the cancelled run current.

Desktop shutdown uses the existing three-second backend termination deadline. Stop admission and request Pi close to preserve pending work; do not interpret close as conversation abort or wait indefinitely for uncooperative code. If cleanup misses the deadline, the forced stop leaves unfinished provider dispatches uncertain and pending work recoverable. Unit 0 tests disconnect, wait cancellation, pause, abort, graceful close and forced kill separately. Reopen reconciles artifacts and attempts before enabling resume; schema/prompt/engine incompatibility blocks with an explicit recovery action.

### Backup and restore

Database-only backup no longer describes a complete review once originals, artifacts and Pi journals exist. Before enabling durable reviews, reject legacy database-only Restore for review-bearing data or any restore that omits its matching journals/checkpoint. Label database-only exports as partial. This guard lands with journal admission, rather than waiting for unit 5. Add a versioned review/project package that identifies all required artifacts and journals by hash. Preserve database-only recovery for data whose semantics remain self-contained.

Maintenance first blocks new work, drains or pauses active runs, closes Pi owners, then acquires the existing database recovery exclusion. Back up each database consistently at that quiescent boundary and write the package manifest last. Never hold the domain SQL semaphore while waiting for an active tool that needs it. Restore validates all hashes, versions and database integrity in staging before replacement; retain a pre-restore package and use a recoverable replacement journal so partial multi-file replacement rolls back on restart. A failed restore preserves the usable existing project.

Restored historical runs do not automatically resume their scheduler: an older package cannot prove that no newer external dispatch or cloud activation occurred. Open them as historical/non-executing state. Starting new work from restored facts requires an explicit new run identity and budget; an offloaded run additionally requires remote ownership reconciliation. Ordinary crash/reopen of the current live data follows the attempt-ledger policy above.

Split the current `Application` wrapper when review operations are added: it presently holds one semaphore around each entire application operation. Retain that permit only around short domain SQL reads/writes and recovery. Rendering, network waits and Pi work run outside it. A separate maintenance admission gate stops new review work before draining; only afterward may maintenance acquire the SQL exclusion. Record this lock order beside the composition root and test correction/export/restore races through the public operations.

## Provider integration and credentials

The primary development and main-track demo route is Meta `muse-spark-1.3` through Pi's Meta Responses adapter. The second evaluated route is Baseten `meta-models/muse-spark-open-1026` through Chat Completions, using the same fixture and application tools. Probe both before unit 4. Promote Spark Open to the primary demo only if it passes those gates and performs useful review work; the open-weight bonus does not justify weakening the main workflow. If the Meta route is unavailable, Baseten is a fallback only after passing the same acceptance cases. Do not switch provider silently during a run.

Use explicit model and endpoint configuration from [Model reference](models.md). Map Moke's `MODEL_API_KEY` to the adapter directly rather than relying on Pi's differently named environment variable. Select one documented context mode per route, test its tool-result and any supported reasoning continuity across reopen, and preserve required opaque protocol state without logging private reasoning. If the adapter changes image dimensions, record the actual transform or reject that path.

Keep the exact organizer Baseten ID `meta-models/muse-spark-open-1026`. Public Baseten docs currently exclude Muse Spark Open from structured outputs and JSON mode. Use schema-validated tool proposals and bounded parse/repair behavior rather than assuming `response_format: json_schema` works. A malformed payload cannot become a successful empty review. Capability records are keyed by provider, endpoint, model and operation; a working text probe does not establish vision, SAM, cancellation or durable retrieval support.

Before adopting either route, test image input, crop/tool round trip, malformed arguments, structured application results, stream interruption, usage, timeouts, response IDs and cancellation/retrieval where available. SAM is its own adapter and capability probe. Cap inline image bytes and account for base64 expansion. Meta background creation has a smaller documented body limit than ordinary media submission; choose background mode only if the actual adapter supports file references and durable IDs. A local loopback file URL is never a provider-accessible artifact.

For packaged local use, Electron owns an OS-protected credential store and passes unwrapped keys only to the Bun backend over the private startup/control channel. Credentials are not renderer capabilities, command-line arguments, exports or logs. On platforms without secure credential storage, fail explicitly or use a user-selected session-only configuration. Development `.env` remains development-only. Add only this narrow credential path; account management is outside the core.

## Modal handoff after local acceptance

Modal remains the selected cloud destination. Preserve that decision while keeping its remote control plane out of the first local finding. Implement a real handoff only after the local correction, revision and recovery gates pass.

The first handoff is deliberately one-way per execution: local checkpoint to one designated Sandbox, followed by remote completion and result import. Returning execution locally or replacing an uncertain live Sandbox requires confirmed termination and an explicit new ownership transfer. Network loss never restarts the local executor.

Use a durable handoff state machine with a unique handoff ID, package hash and monotonically increasing owner generation. The authoritative record lives in the local domain ledger for this one-way handoff. Before activation, persist that local execution is relinquished, permanently stop its run, and bind activation to one recorded Sandbox ID and generation. Start the remote engine inert; it can accept an idempotent activation only for that exact handoff. If Sandbox creation acknowledgement is lost, reconcile by handoff identity before creating another. Never roll back ownership because an acknowledgement times out.

This conservative protocol avoids time-based lease takeover and does not assume that copied owner fields, Modal Volumes or a dictionary provide compare-and-swap fencing. Test all activation/crash windows. Automatic remote replacement, multi-device ownership and cloud-to-local continuation require a separate authoritative conditional-write coordinator and remain outside the first handoff.

The package includes the engine build identity, schema/prompt/tool versions, consistent domain checkpoint, closed Pi journal, outstanding attempt state and the originals/artifacts needed for future crops. Reject incompatible builds or uncertain paid attempts. Give a manifest-based preview of what leaves the device. Supply cloud keys separately through Modal Secrets, never the package.

Run the same Linux Bun engine with a separate remote transport composition. Do not weaken the desktop's loopback-only endpoint to expose it remotely. The backend authenticates remote operations with scoped, expiring capabilities and keeps Modal/control credentials out of the renderer. Reviewer corrections route to the current owner; local evidence remains read-only until importing a version-checked result or a receipt of a remote correction.

Use explicitly configured Sandbox lifetimes and persistent checkpoints on a Modal Volume or an equivalent selected durable store. Verify actual commit behavior at safe boundaries; an exit snapshot is best effort, not the only recovery copy. Persist remote checkpoints before reporting them durable. Reconnect reads a snapshot plus event cursor. Source/version/operation/generation validation makes result import idempotent. No Modal deployment or paid probe is part of writing this plan.

## Verification and evaluation

Use behavioral tests through service/RPC boundaries, temporary real SQLite files and the real compiled Bun process. Inject controllable provider/processing services through Layers. Do not mock SDK internals or add tests that mirror implementation details. Network-free fixtures drive normal CI; live probes are explicit and budgeted.

Required acceptance cases:

1. Coordinate round trips cover rotation, nonzero crop origin, page boxes/user units, different aspect ratios, resize/padding and both Muse/SAM conventions. Target at most one source-render pixel of geometric round-trip error; this measures software transforms, not model localization accuracy.
2. Invalid project/artifact references, out-of-bounds requests, malformed provider results and unexpected unit values are rejected. Truncated/missing evidence never becomes `checked_no_issue`.
3. A correction invalidates only transitive dependents. Concurrent stale output cannot become current; Rev B must not reuse unconfirmed Rev A geometry or measurements.
4. For tools explicitly declared `replay: "safe"`, crash after intent but before domain mutation and again after domain commit but before the Pi receipt. Recovery performs the mutation once or returns its stored result; no second fact/finding is created and no uncertain SAM call is resent.
5. Kill before dispatch, after dispatch without receipt, after a provider ID, during artifact publication, after fact commit, during Pi commit, during pause/cancel, and during package replacement. Reopen presents the correct recoverable or uncertain state.
6. Exercise Pi storage conformance, multi-statement execution/bindings, rollback and rollback failure, queued concurrent calls, expired transaction handles, read-only behavior where used, close/restore races, and journal incompatibility. Verify foreign-key rejection on a fresh connection after reopen and exclusive ownership across two compiled backend processes. Test the compiled executable, not only `bun run`.
7. Fill budgets, fail workers and disconnect subscribers. The event cursor recovers committed progress; memory use stays bounded; closing Electron terminates local work and leaves a recoverable checkpoint.
8. Keep existing origin/auth/top-frame tests and add the new import/artifact/credential boundaries. Cross-project access, arbitrary paths/URLs and secrets in renderer contracts must fail.
9. Export and restore a full review with originals, artifacts, fact history and Pi journal. Reject a corrupted or incompatible package before replacing current data.
10. Conditional on implementing unit 7: cloud tests cover duplicate handoff commands, lost create/activation/import receipts, local restart after relinquishment, stale generations, remote timeout and disconnect. If those fail, the cloud action is unavailable with a specific reason. This case does not block acceptance of the local core when unit 7 is deferred.

Target 12-20 held-out instances across packets, separate from development/demo cases. Include real defects, valid cases, ambiguity, missing calibration and revisions. Compare overview/text, direct detail crops, and the same crops plus SAM using the same reasoning route, rule and declared budget. Report actual counts and denominators, unresolved checks, false alarms, missed in-scope defects, unsupported measurements, manual corrections, cold/warm latency, per-phase usage and known/unknown cost. A smaller completed sample is reported as such.

Run `bun run verify` before handing back implementation changes, plus `bun run package:desktop` and `bun run test:packaged` when native PDF assets, worker compilation or packaged credentials change. Preserve existing cross-platform CI. Use the installed Svelte skills and autofixer when implementing components. Run the selected real-provider acceptance path against the packaged backend before making demo claims.

## Completion criteria

The local core is ready when a fresh packaged launch imports the fixture, completes an evidence-backed check with real Meta activity, survives reopening, supports the false-alarm correction and revision recheck, and exports a reproducible evidence package. All current findings have explicit source/input versions and all unresolved work is visible. Recorded UI actions and tool receipts match the submitted build.

Remaining user-facing choices are the permissioned drawing case, verified rule and applicability, primary demo platform, and actual probe budgets. They block their respective implementation gates, not writing or reviewing this plan. Cloud credentials and deployment approval become relevant only when implementing the optional handoff against an external account.
